# 实验同学开工指南

先读 [开工指南首页](README.md)。详细要求见 [详细设计 3](../详细设计/3_实验计划与执行_详细设计.md)。

## 你负责什么

两个阶段加一个执行器：

| 状态 | 阶段 | 产出 |
|---|---|---|
| `PlanDrafting` | 计划 `stages/plan/` | `plan/experiment_plan.md`、`plan/tasks.json`、`plan/precheck.json` |
| `Executing`、`Analyzing` | 实验 `stages/experiment/` | `runs/<运行编号>/`、`artifacts/aggregates/`、`logs/round_<n>.md` |
| — | 执行器 `runtime/` | 在本机启动、监控、取消、收集实验进程 |

论文同学读你的 `runs/` 和 `artifacts/aggregates/`（通过 `services/runs.py`），GUI 读运行列表和日志。

## 主干已经做好的（不用重复做）

- **数据模型**：`core/models/plan.py`、`run.py`、`aggregate.py` 已按详细设计写好。主干在 `RunRecord` 里加了 `required_metrics`（包装器据此判断“必需指标是否已上报”），见详细设计 3 第 5.2 节。
- **冒烟任务** `tasks/smoke/`：只用标准库，几秒跑完，上报指标 `score`。主干和所有人的测试都在用它。
- **执行器精简版**：`runtime/local.py`（`LocalExecutor`）、`runtime/wrapper.py`（运行包装器）、`runtime/procs.py`（跨平台进程管理）。
  已经做到：运行目录、代码快照、脱离后台运行、指标上报、超时、取消、后台重启后核对、Windows 支持。
  **还没做（你补）**：数据校验（6.2 第 3 步）、完整环境快照（pip freeze、硬件）、GPU 串行、OOM 判定。
- **汇总统计** `services/runs.py`：`list_runs()`、`load_run()`、`compute_aggregate()`（均值、标准差、95% 区间、排除失败和试运行）、`load_aggregate()` 已能用。
- **编码 Agent 的底座** `ctx.llm.tool_loop()`：模型反复调用你给的工具，直到调用 `finish`。权限检查、记账、出错处理都在网关里。
- **假实现** `stages/fakes/plan.py`、`stages/fakes/experiment.py`：现在流程里用的就是它们，**它们写出的文件就是格式样例**。
- **测试替身** `FakeExecutor`：不启动进程，提交后立刻写好运行结果，可以指定哪个运行失败。

## 调用大模型

计划起草、分析用 `ctx.llm.complete(...)`（写法见 [文献指南](文献/文献.md#调用大模型)）。编码 Agent 用 `tool_loop`：

```python
from airesearcher.llm.gateway import tool


@tool(action="write", target="path")          # 写文件前自动做权限检查（例如不允许改 project.yaml）
def write_file(path: str, content: str) -> str:
    """把内容写入项目内的文件。"""             # 这段说明会告诉模型这个工具做什么
    ...


res = ctx.llm.tool_loop(role="exp.coder", prompt_id="experiment/coder", variables={...},
                        tools=[write_file, read_file, run_check], finish_schema=CoderReport, max_turns=15)
res.final        # 模型调用 finish 时给出的结果，已按 CoderReport 校验
```

`exp.coder` 这个角色默认用 `strong` 档模型（见 `configs/models.yaml` 的 `roles`）。

## 测试怎么写

用 `FakeExecutor` 代替真实执行，几百毫秒就能把 9 个运行“跑完”：

```python
from airesearcher.testing.fake_executor import FakeExecutor, FakeOutcome

ex = FakeExecutor(project)                                       # 全部成功；主方法 > 消融 > 基线
ex = FakeExecutor(project, outcomes={
    "E2-seed=1": FakeOutcome.fail(stderr="RuntimeError: CUDA out of memory"),   # 指定某个运行失败
    "E3": FakeOutcome(metrics={"accuracy": 0.61}),               # 指定某个实验的指标
    "trial": FakeOutcome.missing_metrics(),                      # 试运行没有上报必需指标
})
eng = ProjectEngine(project, llm=fake_gateway(project, {...}), executor=ex, retry_delay=0)
```

- `outcomes` 的键可以是运行编号、`task_key`（如 `E2-seed=1`）、实验编号、`kind` 或 `"*"`，按这个顺序匹配；
- 值也可以是函数 `f(record, config) -> FakeOutcome`，例如“第一次失败、重试（`record.retry_of` 不为空）成功”；
- `ex.submitted` 记录了提交顺序。

完整例子见 `tests/test_fakes.py`，运行 `pytest tests/test_fakes.py -q`，看到 `5 passed`。真实进程相关的测试（包装器、取消、重启核对）继续用 `tasks/smoke` 和 `LocalExecutor`，参考 `tests/test_executor.py`、`tests/test_recovery.py`。
