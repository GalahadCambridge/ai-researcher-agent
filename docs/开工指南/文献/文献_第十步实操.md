# 文献第十步：目标保持与证据质量修复

> 本文件保留开发阶段记录。当前状态、复现命令和未完成事项请以 [交接清单](文献_交接清单.md) 为准；全部文档见 [文档目录](README.md)。

本轮负责改进模块的开发质量，不要求开发者批准一个正式的 LoRA 研究题目。LoRA 是测试案例，IdeaPending 是面向最终使用者的审批状态。

## 第一步：保留用户指定的比较目标

目的：避免用户要求比较 A 与 B，模型却生成另一个比较题目。

`goal_scope.py` 从原始 goal 提取明确英文比较句式的两个对象。研究问题、独立的方法/基线条目和假设都必须保留这些对象。缺少文献时记录缺口；不得把替换比较对象写入 open_questions 后继续当作合格输出。校验失败沿用原有一次修复机会，两次均失败则停止该轮。

覆盖范围是明确英文 compare/versus 句式，不是完整自然语言语义判定器。复杂或其他语言目标记录 advisory_only，不能宣称已验证全部研究要求。正式改变比较对象需要明确更新项目 goal；一般修订意见可调整参数和范围。

新增 refine.v2、revise.v2 提示，保留 v1 以便旧缓存回放。模拟案例现在也保留实际输入的比较对象，但仍不代表真实研究结论。

## 第二步：按位置核对引文

目的：避免引文出现在论文其他页却被误判为指定页的证据。

- 支持 p.N、pp.N-M，以及 p.N, p.M 页码列表。仅核对列出的可用页，不跨缺失页或不连续页拼接。
- 原始长引文必须整体精确匹配声明的页码，才允许截取不超过 20 词的短引文。只有开头相同、尾部虚构时仍失败。
- 没有匹配的长引文继续丢弃并降级该条目，其他字段保留。
- quote_checks 保存原引文哈希、词数、来源哈希、检查原因；不把文本匹配当成语义支持。
- 新 reader.v3 提示要求一个条目只表达一个窄范围事实，并准确提供引文所在页码；旧版提示保留。
