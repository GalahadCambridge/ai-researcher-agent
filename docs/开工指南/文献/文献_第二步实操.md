## 2. 查看产物并理解每一层

```powershell
Get-Content -Encoding UTF8 "$ws\idea\brief.json"
Get-Content -Encoding UTF8 "$ws\idea\queries.json"
Get-Content -Encoding UTF8 "$ws\idea\literature.jsonl" | ForEach-Object {
    $_ | ConvertFrom-Json
} | Select-Object paper_id, title, year, access_level, same_as
Get-ChildItem "$ws\idea\search_snapshots"
Get-ChildItem "$ws\idea\search_batches"
```

| 文件 | 作用 | 为什么存在 |
|---|---|---|
| brief.json | 研究对象、变量、关键词和待确认信息 | 把自然语言需求变成可检查的数据 |
| queries.json | 3~5 个子问题，各有 1~2 条英文查询 | 让检索覆盖方法、基线、数据/可行性 |
| search_batches/*.json | 原始快照和标准化论文列表一起保存 | 为每条查询建立可恢复的落盘边界 |
| search_snapshots/*.json | SearchSnapshot 格式，含原始响应和来源标识 | 追溯查询实际返回了什么 |
| literature.jsonl | 去重后的 PaperRecord，每行一篇 | 给筛选、阅读和论文引用核验使用 |

快照的 raw_response.fake=true 明确说明它来自 fixture，没有访问线上 API。
完整快照里的 paper_ids 保留检索源原始返回标识；literature.jsonl 中的 same_as 关联合并的版本。
不满足起始年份的记录由源过滤；合并后最多保留 limits.search_papers 篇，默认 20。
当前按查询和源返回顺序截取，相关性重排属于下一步 screen。

## 3. 关键代码

- `stages/idea/models.py`：IdeaBrief、QueryGroup、QueryPlan；查询词不能为空，结构由 Pydantic 验证。
- `prompts/parse_input.v1.md`：从目标提取信息，不确定内容写 missing_info。
- `prompts/plan_queries.v1.md`：只规划查询，不允许模型编论文。
- `stage.py`：每次 step 做一个阶段动作或一条检索，进度保存在 scratch。
- `sources/base.py`：源协议，约定 search 返回快照和论文列表，get 返回单篇记录。
- `dedup.py`：按 DOI、arXiv ID（忽略版本）、S2 ID、规范化标题和相近年份合并；正式版本优先。
- `demo.py`：只用于离线演示，注入 FakeLLM 和 FakeLiterature。

最重要的调用方式：

```python
out = ctx.llm.complete(
    role="idea.parse", prompt_id="idea/parse_input", tier="strong",
    variables={...}, response_schema=IdeaBrief,
)
brief = out.parsed
```

`out.parsed` 是通过结构校验的结果；代码随后用项目 task 和用户 constraints 覆盖模型可能改写的值。
提示文件已版本化；以后修改提示语义时新增 v2 文件，不覆盖已有 v1。

## 4. 恢复与失败行为

已落盘的 brief、queries 和检索批次在重入时会复用。
每条检索批次同时保存原始响应和标准化记录，之后即使汇总前重启，也不必重复该查询。
如果请求成功但批次尚未保存就崩溃，恢复时仍可能重新请求；这里不承诺外部请求严格只执行一次。
汇总时只追加新增或变化的记录；重复汇总不会重复追加相同记录。
网络类异常返回可重试 Error，不跳过失败查询、不制造替代文献。
第二轮当时尚未接真实源；第三轮已加入限流、重试和换源，具体见 [第三步实操](文献_第三步实操.md)。
空结果会保存空文献文件，并在下一步待筛选处暂停。

阶段目前没有自动处理模糊研究目标的提问流程；筛选、阅读、审批与修订仍待实现。真实源已在第三轮接入。

## 7. 下一轮会用到的官方资源

- [Semantic Scholar API 文档](https://api.semanticscholar.org/api-docs/)：看 Paper relevance search、fields 和 externalIds。
- [arXiv API 用户手册](https://info.arxiv.org/help/api/user-manual.html)：看 Query Interface、Atom Response 和论文版本。

两者响应格式不同，适配器要把它们转换成相同的 PaperRecord 和 SearchSnapshot。
可以手动探测下面两个请求，观察原始响应（本轮演示没有执行这些在线检索命令）：

```powershell
curl.exe "https://api.semanticscholar.org/graph/v1/paper/search?query=LoRA&limit=3&fields=title,year,externalIds,abstract,citationStyles"
curl.exe "https://export.arxiv.org/api/query?search_query=all:LoRA&start=0&max_results=3"
```

前者预期返回 JSON，后者返回 Atom XML；若遇到限速或服务异常，保留状态码供下一轮排查。
