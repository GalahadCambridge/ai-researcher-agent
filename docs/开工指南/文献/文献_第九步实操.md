# 文献第九步：英文文档、审批与修订（节点 6）

> 本文件保留开发阶段记录。当前状态、复现命令和未完成事项请以 [交接清单](文献_交接清单.md) 为准；全部文档见 [文档目录](README.md)。

目标：把结构化选题发布为英文 selected.md，绑定准确版本提交审批；收到反馈后保留历史、更新评分与差异表。到 IdeaPending 停止，用户决定是否批准。运行流程不等于研究结论已证实。

## 生成与校验

write 不再调用模型。代码从同一份 SelectedIdea 渲染 YAML 头部和英文正文，并用共享 parse_selected_md 还原比对。检查任务、指标、预算、登记引用、弱证据标记和必要文件哈希。validation_report.json 固定 selected.md 和支持文件的版本。

submit 提交 NeedsApproval，由共享引擎创建审批、进入 IdeaPending。摘要包含待核验评分、未解决冲突和所有 open_questions；代码不自动批准真实选题。批准时间与版本由共享审批记录保存，不通过改写待审批文档伪造批准时间。

## 退回与恢复

- changes_requested：读取被退回的准确版本及意见，调用 revise，重新生成评分、差异表和文档。
- rejected：共享引擎先询问重写还是结束，选择 redo 后才修订。
- 下游阶段返回 IdeaDrafting：读取 entry 原因，保留已批准计划可能失效的提示。
- 每次反馈有独立 selection_round，保留 started、调用追踪和结果；恢复不重复成功调用。
- 需要更多文献时，在 idea/revision_literature/<round>/ 独立检索；按外部 ID、标题、年份去除已有论文，只对新增论文做全文与阅读。
- 旧卡片、原文快照和缺口候选保留，新增材料合并后重新 refine。历史档案保留旧文档和修订父版本。

## 真实实验发现的问题及修复

1. 布尔查询直接交给跨源关键词适配器会无结果。新增 plan_queries.v2.md 和输入校验：最多 6 个关键词，去除布尔/字段语法。原版本保留；LoRA 示例支持 --resume --repair-queries，并归档原计划与确定性修复说明。
2. 单个引文超过 40 词曾导致整卡失败。现在丢弃该引文、标记 quote_verified=false、降级为低置信度 agent_inference，并保留其他阅读字段。阅读提示 v2 建议引文不超过 20 词，纯 verify 仍拒绝超长引文。
3. 已付费模型回复可以回放。recovery.py 验证原检索/PDF档案哈希，复制到全新工作区；按原调用记录固定提示版本，用 replay 模式恢复阅读。旧失败卡与下游草稿保留在原项目，不复制到新项目。缓存不完整时停止，不自动支付补读费用。
4. 已完成调用可以核对并结算预留：同时核对官方密钥累计费用和本地 token 费用估算，取较高值，加 50% 和 0.01 美元余量；保留原始每次预留与所有记录。未知费用禁止自动结算，累计上限始终为 2 美元。

评分引用修复：evidence.py 仅归一化能唯一映射到登记卡片和条目的 paper/role/item 别名。selection.py 将已知选题字段及循环评分理由移出论文证据、标为待核验。recovery.py 可免费重新校验已付费评分缓存，归档原始回复；未知来源继续拒绝。真实结果和人工待办见 [节点6验证记录](文献_节点6验证记录.md)。
