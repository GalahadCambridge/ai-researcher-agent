## 2. 固定输入与来源检查

目的：使协调、复核及恢复使用同一份证据。

merge.py 读取 reading_input.json、reading_status.json、gaps.json 和成功卡片：
- 检查论文存在于已归档 literature.jsonl；
- 检查文本 SHA-256、卡片身份、实际 based_on 和安全的卡片文件名；
- 在合并快照中重新核对引文，不覆盖原始卡片；
- 检查缺口引用指向已有条目；
- 保存 merge_input.json 和整体哈希，恢复时重新验证。

本轮输入固定；更换材料或目标时使用新项目，增量修订暂未实现。快照中的文本来自本轮阅读输入，不是新增检索证据。
文件：merge.py、models.py。

## 3. 规则候选与协调合并

目的：发现待核查分歧，并形成有来源的主题和可行性说明。

conflicts.py 按同一论文、同一字段分组，对不同卡片的数值、显式可得性、可识别数据集名称差异生成候选。
90 与 90.0 等价；未提及和模拟占位不触发规则；普通措辞不同不会直接认定为冲突。
规则是启发式，可能漏检或误报。默认 multi 的两类阅读字段不重叠，跨字段和跨论文的语义分歧由协调者补充检查。空冲突列表不证明观点一致。

协调者调用 ctx.llm.complete(tier="strong")，接收卡片、已有缺口和规则候选。全部材料通过 wrap_untrusted 包裹，不提供工具。
综述判断、可行性、缺口和冲突候选都要引用 ref，例如 arxiv_2106.09685__methods#0。
程序检查引用有效、不重复，且每张成功卡片至少被覆盖一次；不要求每个字段都写入综述。
协调者可以补充冲突，不能直接决定解决状态；同一引用集合的重复冲突会合并。

文件：conflicts.py、merge.py、models.py、coordinator_merge.v1.md。

## 4. 原文复核与恢复

目的：根据原文检查分歧，避免多数票覆盖少数意见。

- 每步最多处理一个冲突；每个冲突最多一次复核入口调用，每轮最多 3 次；
- 只提供冲突条目和相关原文窗口，每个条目最多 400 词；
- p.N 定位只在对应页选片段；缺少原文时保留 needs_human；
- 复核使用 strong，关闭 JSON 自动修复重试（max_retries=0）；网关传输重试属于独立层，所以“一次复核”不等于供应商只收到一个 HTTP 请求；
- resolved_by_reread 要求被采纳引用属于本冲突、原卡条目为已核对引文的作者陈述，且复核提供的 ≤40 词引文匹配该条目的原文窗口；
- 非法引用、伪造引文、模型异常、证据不足或达到上限时保留 needs_human；
- 调用前保存 started 回执；恢复时如只有 started，标为 interrupted / needs_human，不自动重调。

原始卡片不被改写，账本保留全部立场、复核理由和采纳条目。原文可以支持少数立场，不能按多数票决定事实。
回执保存实际提供的原文窗口；成功返回时记录模型追踪和网关用量/费用，事件日志记录原因及结果。失败或中断可能没有返回用量，不能据此按零费用计算，应结合 .llm/calls.jsonl 和供应商记录核对。
resolved_by_reread 表示模型复核且通过文字/引用门槛，不是程序证明论断正确。

文件：conflicts.py、merge.py、adjudicate_conflict.v1.md。

## 5. 发布综述与状态

目的：同时提供后续程序可读取的输入和人可以核查的英文报告。

| 产物 | 作用 |
|---|---|
| idea/merge_input.json | 固定卡片、文本、缺口、失败任务和哈希 |
| idea/merge_coordinator.json | 协调输出、冲突候选和追踪；恢复时复用 |
| idea/conflict_reviews/K*.json | 单冲突回执、原文窗口、复核结果和费用信息 |
| idea/conflicts.json | 所有立场、解决状态、采纳条目和复核次数 |
| idea/reading_summary.json | 主题、缺口、可行性、摘要来源、失败阅读和未解决冲突 |
| idea/reading_summary.md | 带 paper_id 和 card_id#item_index 的英文综述 |
| idea/merge_status.json | 卡片数、冲突数、复核解决数、人工待查项和调用次数 |

摘要、推断、引文失败、未解决分歧或未被复核采纳的条目，会使相关综述判断保留 to_verify。
上游缺口不会因协调者漏写而消失；证据不足或涉及未解决分歧的缺口降为 to_verify。
原始 reading_cards、gaps.json、literature.jsonl 不被合并模块改写。
缺少最终文件时可从输入/回执重建；相同内容不重复归档。
Markdown 转义 HTML 并折叠外部文本换行，减少原始 HTML 和伪造标题进入报告。

完成后 phase=refine 并暂停，尚未生成 selected.md、评分和审批。
文件：render.py、merge.py、stage.py、demo.py。

~~~powershell
$singleMergeWs = Join-Path $env:TEMP ("air-merge-single-" + [guid]::NewGuid().ToString("N"))
python -u -m scripts.literature.demo --workspace $singleMergeWs --read-papers 2 --reading-mode single
Get-Content -Encoding UTF8 "$singleMergeWs\idea\reading_summary.md"
~~~

预期 2 张 single 卡，进入相同合并流程；这不是质量对比实验。
