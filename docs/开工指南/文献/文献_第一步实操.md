## 1. 进入环境

```powershell
cd D:\study\GitHub\ai-researcher-agent
conda activate air
$env:PYTHONUTF8 = "1"
git branch --show-current
air --help
```

当前已安装 Python 3.12、项目和开发依赖，无需重新建环境。若在另一台电脑首次安装：

```powershell
conda create -n air python=3.12 -y
conda activate air
pip install -e ".[dev]"
```

`-e` 表示修改仓库代码后直接生效；`[dev]` 安装 pytest、ruff 等开发工具。
`PYTHONUTF8` 解决 Windows GBK 终端无法输出勾号的问题。每个新终端都要设置。

## 2. 验证现有假流程和示例

```powershell
pytest tests/test_e2e_engine.py::test_full_flow_to_completed tests/test_example_stage.py -q
```

预期 3 passed。端到端测试从创建项目跑到 Completed，包含选题退回修改、四次审批和九个小实验；模型和阶段用假实现，不需要 Key。实验会真的启动本地小脚本。测试里的审批由测试代码模拟。
这验证的是引擎与交接格式，不代表真实文献检索完成，也不验证后台 HTTP 连接。

亲手体验后台和审批时，另开两个已激活 air 的终端。
终端 1：

```powershell
$env:PYTHONUTF8 = "1"
air serve
```

终端 2：

```powershell
$env:PYTHONUTF8 = "1"
air new --idea "比较三种方法在冒烟任务上的得分差异" --task tasks/smoke
air status --wait
air approvals
```

按输出的实际审批编号执行（把占位符换掉）：

```powershell
air show <审批编号>
air approve <审批编号>
air status --wait
```

对选题、计划、日志、手稿依次重复，最后状态是已完成。查看后台接口：
http://127.0.0.1:8765/docs （仅后台运行后可访问）。
本次自动验证通过测试完成；后台手动演示供你自己练习，尚未替你执行这些人工审批。

运行示例阶段，观察一次模型输出如何变成归档和审批：

```powershell
$exampleWs = Join-Path $env:TEMP ("air-example-" + [guid]::NewGuid().ToString("N"))
air dev new-workspace $exampleWs --idea "比较两种小模型在情感分类上的表现" --impl idea=example
air dev run-stage example --workspace $exampleWs --steps 3 --fake-llm
```

预期出现 Continue、NeedsApproval，再停在等待审批。临时项目不加入 Git。
