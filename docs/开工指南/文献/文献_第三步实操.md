## 1. 本次验证结果

2026-10-18，本机实际探测：S2 无 Key 搜索返回 429（无 Retry-After），arXiv 返回 200 Atom XML。
演示执行 3 条查询，S2 初次失败后分别重试 3 次，随后切换 arXiv，最终保留 20 篇去重记录。
这些是实时检索候选，没有经过相关性筛选，不能将前 20 篇视为最相关的论文。
S2 的成功响应转换已用模拟 HTTP 测试验证；本轮未在线取得 S2 成功响应。
线上结果来自 arXiv，后续响应、论文数和耗时可能变化。

## 2. 运行真实检索演示

PowerShell：

```powershell
cd D:\study\GitHub\ai-researcher-agent
conda activate air
$env:PYTHONUTF8 = "1"
$liveWs = Join-Path $env:TEMP ("air-literature-live-" + [guid]::NewGuid().ToString("N"))
python -u -m scripts.literature.demo --workspace $liveWs --live-retrieval --timeout 180
```

使用 `-u` 让每一步及时显示。模型是 FakeLLM，检索源是真实 HTTP API；不会发起付费模型调用。
`--timeout` 限制演示的调度时间，正在进行的单次 HTTP 请求另有 25 秒超时。
若没有 S2_API_KEY，仍可以运行；可能遇到限流再换源。
已有合法 S2 Key 时可在自己终端设置环境变量 S2_API_KEY，不要将密钥写进仓库或分享给别人。

查看结果：

```powershell
Get-Content -Encoding UTF8 "$liveWs\idea\literature.jsonl" | ForEach-Object {
    $_ | ConvertFrom-Json
} | Select-Object paper_id, title, year, source, access_level
Get-Content -Encoding UTF8 "$liveWs\research_log.jsonl" | Select-String 'literature.source_switched'
Get-ChildItem "$liveWs\idea\search_snapshots"
```

成功结果保存为 search_batches 和 literature.jsonl；HTTP 错误响应也保存在 search_snapshots 中。
程序不会因为只拿到 PDF 链接就将论文标成 full_text，目前最多 abstract_only。

## 3. 离线回放本次结果

保留同一终端中的 $liveWs，然后：

```powershell
$replayWs = Join-Path $env:TEMP ("air-literature-replay-" + [guid]::NewGuid().ToString("N"))
python -u -m scripts.literature.demo --workspace $replayWs --replay "$liveWs\idea\search_batches"
```

回放只读本地批次，不会联网；查询、年份、所需数量必须与保存的数据匹配。
也支持真实原始快照目录 search_snapshots；批次回放更适合精确复现，因为保存了已标准化的全部记录和时间字段。
上一轮 FakeLiterature 的原始快照只含简化信息，因此回放那一轮数据时也应选择 search_batches。

用全部字段对比结果：

```powershell
$env:AIR_COMPARE_LIVE = $liveWs
$env:AIR_COMPARE_REPLAY = $replayWs
python -c "import os; from pathlib import Path; from airesearcher.services.literature import load_papers; a=load_papers(Path(os.environ['AIR_COMPARE_LIVE'])); b=load_papers(Path(os.environ['AIR_COMPARE_REPLAY'])); assert a == b; print('Replay matches:', len(a))"
```

这次实际验证输出 Replay matches: 20。没有快照时会明确返回错误，不自动改用线上源。

## 4. 各文件职责

| 文件 | 本轮变化与作用 |
|---|---|
| sources/http.py | 新增；受权限控制的 HTTP、单连接节流、Retry-After 解析；需要等待时抛 SourceWait |
| sources/metadata.py | 新增；统一 DOI/arXiv ID、引用键、BibTeX，解决引用键重名 |
| sources/semantic_scholar.py | 新增；JSON → PaperRecord，保存失败响应，提供 search/get |
| sources/arxiv.py | 新增；Atom XML → PaperRecord，控制查询格式与年份，提供 search/get |
| sources/router.py | 新增；初次失败后重试 3 次，之后换源，重试进度保存在 scratch |
| sources/replay.py | 新增；严格从本地快照/批次回放，缺少匹配时错误退出 |
| stage.py | 修改；未注入测试源时使用真实源；配置 replay_snapshots 时使用回放源；SourceWait 转为引擎 Wait |
| demo.py | 修改；新增 --live-retrieval、--replay、--timeout，演示模式由命令明确选择 |
| tests/test_literature_sources.py | 新增；元数据、缺失信息、权限、限流、重试换源、回放等模拟 HTTP 测试 |
| tests/test_idea_stage.py | 修改；把旧的“真实源未实现”测试更新为“回放缺少快照”检查 |

sources/ 均位于 airesearcher/stages/idea/ 下。未修改 engine、core、llm 等主干实现。

## 5. 正式流程怎样选源

- `IdeaStage(source=FakeLiterature())`：测试时显式注入假源。
- `IdeaStage()`：真实源，S2 优先，失败重试后转 arXiv。
- 项目的 `literature.replay_snapshots` 指向快照/批次目录：回放源，绝不联网。
- 通用 `air dev run-stage ... --fake-llm` 的默认模型回复不适配 IdeaBrief，当前仍使用 demo 做可复现开发演示。

真实模型接入和模型 Key 配置属于后续一步。当前不要把 OpenRouter Key 当作 S2 Key。
