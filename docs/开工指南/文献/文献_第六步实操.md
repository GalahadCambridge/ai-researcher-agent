## 1. 固定阅读输入

目的：保证同一项目中各角色读取相同的材料，并可在中断后复现。

readers.py 只处理 selected_for_reading=true 的文献，优先读取已有 fulltext_path 指向的文本，最多 12,000 词；文件缺失或不可读则降为摘要并记录警告。
没有正文或摘要的论文不会调用模型，也不会编造卡片；对应任务按失败策略记录。
实际文本、研究目标、模式、来源路径和文本 SHA-256 保存为 idea/reading_input.json。
此文件固定本轮输入；更换材料、目标或阅读模式时使用新的空工作目录。本轮尚未实现审批退回后的增量阅读。

修改文件：readers.py；调用已有文献读取、归档服务，不修改已冻结的核心模型。

## 2. 区分阅读角色与结构校验

目的：让不同角色完成不同任务，再为后续协调者提供结构相同、职责不同的证据。

| 模式/角色 | 内容 | 每篇卡片数 |
|---|---|---|
| multi / methods | 方法、任务、数据集、指标、基线、主要结果、设置、局限，共 8 项 | 1 |
| multi / feasibility | 代码、数据、计算资源、依赖、许可、复现风险，共 6 项 | 1 |
| single | 合并以上 14 项，供后续对比实验使用 | 1 |

通过 ctx.llm.complete(tier="fast") 调用网关，论文文本使用 wrap_untrusted 包裹。
模型只返回 ReaderOutput：条目和与研究问题的关系；程序要求角色字段恰好各出现一次，不能漏项、重复或增项。
模型不得决定 paper_id、card_id、based_on、模型调用追踪等字段，这些由程序根据实际任务和网关返回值填入 ReadingCard。
模型记录来自网关，不能把模拟后端的模型标签当作真实 API 调用证明。

新增/修改：models.py、readers.py，以及 methods_reader.v1.md、feasibility_reader.v1.md、single_reader.v1.md。

## 3. 核对原文引文

目的：阻止不存在于阅读材料中的片段以“作者明确陈述”的身份进入后续分析。

quotes.py 使用 Unicode 归一化、大小写归一、标点分词和断行连字符处理。
片段最多 40 个归一化词元；少于 10 个词元必须完整匹配，更长片段要求至少 90% 的连续词元匹配。
只读摘要时 source_loc 必须为 abstract；p.N 形式的页码必须存在于输入的页码标记中。
quote_verified 由代码重新计算，不信任模型填写的值。
作者陈述没有引文或引文核对失败时，降为 agent_inference、low confidence；过长引文和非法字段等使任务校验失败。

这只是文字匹配：不证明引文支持卡片论断，也不验证章节/表格定位或引文确实位于所填页内。语义正确性仍需真实模型实测和人工抽查。

新增：quotes.py；在 readers.py 中于保存之前调用。

## 4. 并发、重试与恢复

目的：控制调用数量，保留成功结果，使单个坏结果不会阻塞所有论文。

每篇论文乘以角色构成任务列表，存在 scratch 中；线程池并发数默认为 limits.reader_concurrency=2，每次 step 最多调度 6 项。
工作线程只调用模型并校验，任务状态和阅读卡由调度线程写入。
任务一次失败后再尝试一次；第二次仍失败则记为 failed，继续其他任务。
这是任务级重试；网关自身的 JSON 修复/网络重试属于另一层，一项任务不保证只产生一次底层模型请求。

每项状态和完整卡片先写到 idea/reading_receipts/<card_id>.json，再投影为 idea/reading_cards/<card_id>.json。
恢复时读取回执、核对输入哈希和卡片身份、重新核对条目；卡片文件缺失可从回执重建，不重复已完成的阅读调用。
失败回执也保留尝试次数，恢复不清零。完成后生成 idea/reading_status.json，列出成功、失败、引文统计和来源警告。

新增：readers.py、tests/test_idea_readers.py。

## 5. 生成研究缺口候选

目的：把“已有研究可能还缺什么”转换为可追溯、可在下一步审查的候选列表。

多角色模式取 methods 卡；single 模式取卡片中的方法字段。传给 gap_analyst 的每个条目都有 ref，例如 arxiv_2106.09685__methods#0，索引从 0 开始。
程序拒绝不存在的引用和重复 gap_id。
没有任何“全文 + 作者陈述 + 引文通过”的引用时，supported 强制降为 to_verify；程序不会自动把模型给的 to_verify 升级。
即使状态是 supported，也仅表示通过最低证据门槛，不证明缺口论断正确或全球研究新颖性。

保存 idea/gaps.json，包括候选、调用追踪、未完成阅读任务。没有卡片时跳过模型，保存空候选。
完成后 phase=merge；协调合并、冲突检测、最终选题和审批尚未实现。

新增/修改：readers.py、models.py、gap_analyst.v1.md、stage.py。

目的：无需密钥即可检查结构、产物和调度；演示的阅读内容是明确标注的模拟占位，不代表真实语义分析。

模拟 gap 返回空列表，也不能解读为没有研究缺口。

预期 2 张 single 卡，每张 14 个条目；多角色每篇 2 张卡，总字段数相同。以上不构成单/多 Agent 质量比较实验。

可选加入真实 PDF 输入（会联网下载 1 篇，模型回复仍是模拟）：


不加 --fetch-fulltext 不下载 PDF；--live-retrieval 只切换元数据检索，不能启用真实模型。当前 demo 没有真实模型开关。
本轮未使用付费模型 API，也未写入 API 密钥；真实模型的语义质量验证仍待进行。

## 9. 对照源码学习的官方资源

先看 readers.py 的 _read_one/read_step，再对照 [Python ThreadPoolExecutor 官方文档](https://docs.python.org/3/library/concurrent.futures.html#threadpoolexecutor) 理解“提交任务 → Future → 获取结果”。本项目显式设置 max_workers，因此不依赖 Python 版本间不同的默认并发数。
看 models.py 的 ReaderOutput/ResearchGap，再对照 [Pydantic Models 官方文档](https://docs.pydantic.dev/latest/concepts/models/) 理解 JSON 如何转换为经过结构校验的对象。类型校验只能约束结构和显式规则，无法替代论文内容真实性判断。
