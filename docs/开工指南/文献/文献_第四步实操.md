## 1. 定义评分结构

目的：让模型结果可检查，后续代码可以稳定排序。

- models.py 新增 PaperRelevance 和 ScreenBatch。
- score 必须为 1~5 的整数，不接受布尔值或数字字符串；reason 不能为空。
- 每批结果必须对输入中的每个 ID 评分一次；未知、重复和遗漏 ID 都返回 Error，不写入有效评分批次。

## 2. 批量评分

目的：控制单次输入大小，并让中断后可以从已完成批次继续。

- 每次最多 10 篇，使用 tier=fast。
- prompts/screen.v1.md 给出分数锚点，要求只参考标题和摘要。
- 标题和摘要通过 wrap_untrusted 包装，其中的指令不会成为模型应执行的任务。
- 每个 step 最多调用一次评分；成功后立即保存 screen_batches，再返回 Continue。
- 批次中记录模型配置名、prompt_id/version 和 call_id；演示使用假后端，配置名不代表本次真实调用过该模型。

## 3. 选择精读论文

目的：控制后续全文获取和阅读成本，默认最多 8 篇。

- 按 score 降序，分数相同时保持原始候选顺序。
- 没有摘要、也没有已知可读全文的记录仍可按标题评分，但不会进入精读名单。
- 按详细设计 6.2：如果最高分名单全部只覆盖一个子问题，则为其他有可读候选的子问题预留位置，再按分数补齐。
- 有限名额或缺少候选导致无法覆盖的子问题，写入 uncovered_subquestions。
- 如果低分论文仍因数量和覆盖要求入选，会在 low_relevance_selected 中列出；当前没有另加最低分阈值。
- limits.read_papers=0 表示不选择精读；负值报错。

## 4. 保存产物

目的：让后续阅读、GUI、评价实验读取同一套结果。

| 产物 | 内容 |
|---|---|
| idea/screen_input.json | 固定本次筛选的需求、查询计划和候选列表，恢复时复用 |
| idea/screen_batches/*.json | 每批评分及调用来源记录，恢复时不重复已落盘批次 |
| idea/literature.jsonl | 追加新版本，写入 relevance.score/reason 和 selected_for_reading |
| idea/screening.json | 入选 ID、数量、覆盖调整、无可读内容列表和未覆盖子问题 |

literature.jsonl 是只追加日志，同一个 paper_id 可能有多行；用 services.literature.load_papers() 读取，最后一行生效。
不要通过原始行数计算论文数，也不要把最初的 selected_for_reading=false 当作最终筛选结果。
已完成筛选时停在 fulltext，只表示需要下一步获取全文；不代表全文已经下载。
内部 phase 不改变主干的对外交接格式。

## 5. 实际运行

PowerShell：

```powershell
cd D:\study\GitHub\ai-researcher-agent
conda activate air
$env:PYTHONUTF8 = "1"
$screenWs = Join-Path $env:TEMP ("air-screen-" + [guid]::NewGuid().ToString("N"))
python -u -m scripts.literature.demo --workspace $screenWs
```

本次实际演示：13 篇本地候选 → 10+3 两批评分 → 8 篇入选 → phase=fulltext。

查看报告和最终入选记录：

```powershell
Get-Content -Encoding UTF8 "$screenWs\idea\screening.json"
Get-Content -Encoding UTF8 "$screenWs\idea\literature.jsonl" | ForEach-Object {
    $_ | ConvertFrom-Json
} | Group-Object paper_id | ForEach-Object {
    $_.Group[-1]
} | Where-Object selected_for_reading | Select-Object paper_id, title,
    @{Name='score'; Expression={$_.relevance.score}},
    @{Name='reason'; Expression={$_.relevance.reason}}
Get-ChildItem "$screenWs\idea\screen_batches"
```

在旧的真实检索批次上运行筛选（不重新联网）：

```powershell
$snapshotDir = Read-Host "请输入以前项目 idea\search_batches 目录的完整路径"
$screenReplayWs = Join-Path $env:TEMP ("air-screen-replay-" + [guid]::NewGuid().ToString("N"))
python -u -m scripts.literature.demo --workspace $screenReplayWs --replay $snapshotDir
```

本轮实际验证：20 篇真实论文的保存记录 → 两批模拟评分 → 8 篇入选。
逐条对比后，原始论文元数据保持一致，新增了 relevance 与 selected_for_reading。
研究目标与查询仍是演示预置的 LoRA/低资源分类场景，回放目录必须包含匹配的查询和参数。
