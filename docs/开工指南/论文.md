# 论文同学开工指南

先读 [开工指南首页](README.md)。详细要求见 [详细设计 4](../详细设计/4_论文撰写与绘图_详细设计.md)。

## 你负责什么

项目处于 `Writing` 状态时，引擎调用你的阶段 `stages/writing/`。你还负责三个 skill 和证据核验服务：

| 产出 | 给谁 | 格式 |
|---|---|---|
| `artifacts/figures/<fig_id>/`（图、绘图脚本、数据、`figure.json`） | GUI（图表页） | 详细设计 4 第 3.1 节；数据模型 `core/models/figure.py` |
| `paper/`（LaTeX、PDF、`air_values.tex`、`claims.jsonl`、核验报告） | GUI（论文页、证据跳转） | 详细设计 4 第 3.2~3.4 节；数据模型 `core/models/claim.py` |
| `skills/scientific-plotting/`、`latex-writing/`、`claim-review/` | 你的阶段 | 详细设计 4 第 5、7、8 节 |
| `services/evidence.py` 的 `check()`、`trace()`、`audit()` | 主干 API、GUI | 详细设计 4 第 8.4 节 |

## 主干已经做好的（不用重复做）

- **数据模型**：`core/models/figure.py`、`claim.py`（`Claim`、`CheckReport`、`CompileReport`、`EvidenceTrace`）已按详细设计写好。
- **证据核验服务的第一版** `services/evidence.py`：`check()` 已做四项检查——数字与重算值对不上（`NUM_MISMATCH`）、用了过期的结果（`STALE_EVIDENCE`）、结论与数据方向相反（`CONTRADICTED`）、引用不在文献记录里（`CITATION_NOT_IN_ARCHIVE`）；`trace()` 已能返回一条论断的证据链。其余检查项和 `audit()` 是你的。
- **读实验结果**：`services.runs.load_aggregate(root, "C1")` 读汇总结果，`services.runs.load_run(root, run_id)` 读单个运行。不要自己解析 `runs/` 下的文件。
- **读文献**：`services.literature.load_papers()`、`verify_citation()`、`bibtex_for()`。
- **假实现** `stages/fakes/writing.py`：现在流程里用的就是它。其中 `compile_paper()` 已经封装了 `latexmk` 调用（禁用 shell-escape、编译失败写报告），可以直接拿去用或改进。
- **skill 加载与版本管理**：`ctx.skills.load("scientific-plotting")`，以及 `air skills verify`（见下文）。
- **样例项目里故意放了 2 条错误论断**：`fixtures/sample_project/paper/claims.jsonl` 的最后两条，一条数字不对、一条结论与数据相反。

## 先做这几件事

1. 确认本机能运行 `latexmk`（macOS：MacTeX；Windows：MiKTeX 或 TeX Live；Linux：`texlive-full`）：

   ```bash
   latexmk -v
   ```

2. **用样例项目的汇总结果画图**，先不接阶段，写成独立脚本跑通三种图：

   ```python
   from airesearcher.services import runs
   from airesearcher.testing.sample import SAMPLE_PROJECT

   agg = runs.load_aggregate(SAMPLE_PROJECT, "C1")
   for row in agg.rows:
       print(row.group, row.metric, row.mean, row.ci95, row.n)   # 每组的均值、95% 区间、种子数
   ```

3. 把绘图做成 skill `skills/scientific-plotting/`（第一个 PR 就交这个，见下一节）。
4. 再建 `airesearcher/stages/writing/stage.py`（`name = "writing"`，提供 `create_stage()`），先走通“关闭证据检查”的路径。
   用自己的实现：`air dev new-workspace /tmp/ws --from fixtures/sample_project`，把 `project.yaml` 的 `dev.stage_impl` 改成 `{writing: real}`，
   再用 `air dev run-stage writing --workspace /tmp/ws --state Writing`。

## 写一个 skill

照着 `skills/example-skill/` 建目录：

```text
skills/scientific-plotting/
├── skill.yaml        # 名字、版本、说明、检查函数、依赖（如 matplotlib>=3.8）
├── SKILL.md          # 给模型读的规则（会拼进提示）
├── scripts/          # 确定性脚本，如 plot_bar.py
├── validators.py     # 检查函数：输入是输出结果，返回问题列表，没问题返回 []
└── sample/
    ├── input/        # 小样例的输入（如一份汇总结果 JSON）
    ├── run.py        # def run(skill, input_dir, out_dir)：用输入产生输出
    ├── expected/     # 预期输出：.json 比内容，文本逐行比，图片和 PDF 只要求存在
    └── bad/          # 故意画错的输出（如没有坐标轴标签），检查函数必须能发现
```

写好或改了版本号之后：

```bash
air skills verify scientific-plotting
```

全部 ✓ 后，它会把新版本写进 `skills/registry.yaml`，**把这个文件一起提交**。没有验证过的版本，`ctx.skills.load()` 会拒绝加载
（开发中想先试用，设置环境变量 `AIR_SKILLS_UNVERIFIED=1`）。CI 会对所有 skill 跑一遍验证。

## 测试怎么写

1. 新建文件 `tests/test_paper_sample.py`，内容如下（参数写 `sample_project`，就会拿到一份样例项目的副本，改坏了不影响原样例）：

   ```python
   from airesearcher.services import evidence


   def test_wrong_claims_are_caught(sample_project):
       report = evidence.check(sample_project.root)
       assert report.counts["blocker"] == 2     # 样例里故意写错的 2 条论断必须被检出
   ```

2. 运行：

   ```bash
   pytest tests/test_paper_sample.py -q
   ```

3. 看到 `1 passed` 就对了；看到 `failed` 会列出哪一行没通过。

写作阶段的端到端测试写法见 [文献指南](文献/文献.md#测试怎么写)，把 `stages={"idea": ...}` 换成 `stages={"writing": ...}`；
建项目时加 `dev={"compile": False}` 会跳过 LaTeX 编译，没装 TeX 的电脑（包括 CI）也能跑。

## 交接前自查

```bash
air dev check /tmp/ws --owner 论文
```

两条硬规则：**论文里的数字只能来自 `air_values.tex` 的宏**（由结果文件生成，不让模型手写数字）；观察到的结果和对结果的解释要分开写。

## Writing 恢复与文件所有权

语义 reviewer / reviser 每个单元自动最多尝试两次。拒绝的原始回复、call id、
错误和每次尝试均保留在 `paper/.writing/*-attempts.json` 及 Archive；重启不会
再次调用已经记录回复的模型。调用中断但没有回复时，费用不确定，先询问用户。
耗尽后 GUI 或 CLI 的待答问题提供 `retry`（额外一次调用，可能产生费用）、
`skip`（本单元未完成，保留 major `SEMANTIC_INCOMPLETE` 交人工审批）、`end`。
`end` 是无人值守的安全默认选项。跳过不是 PASS，也不清除已有 major/blocker。
CLI 可先 `air question <project>` 查看问题，再通过 `air answer --help`
查看当前命令格式；GUI 在待答问题中选择相同选项。

已生成章节的合法人工编辑会保留并重新验证。无 receipt 的章节、安装过程中的
章节冲突、或被修改的代码所有 `claims.jsonl` / `air_values.tex` 会出现 reconciliation
问题。选择 `restore` 会先把冲突原始字节归档，再恢复精确 receipt 内容；没有可信
receipt 的章节会在备份后重新生成。选择 `end` 保留当前文件并结束。恢复后仍要经过
正常的 evidence、numeric、模板、编译和最终审批校验，不允许“忽略并继续”。
不要手改 `paper/.writing/`、`claims.jsonl`、`air_values.tex`、图表脚本或归档证据。
需要修改实验结论时，应更新来源并按正常 Plan/Experiment approval 流程重建证据。

provenance 不匹配、Aggregate/run graph 无效、过期或矛盾的证据、非法模板、
被改坏的 claim wrapper、修订事务中的其他 source 冲突仍 fail closed。
修订事务目标本身的人工冲突可以在备份后恢复已接受的精确内容；不接受其他来源变化。修正来源或
恢复其精确 archived version 后再 Resume；不要编辑 receipt 来绕过检查。对无法安全
自动恢复的历史 review/事务冲突，应保留工作区供人工核对，并使用新的工作区重现。

图表使用固定顺序的已安装 CJK 字体作为后备，不下载或捆绑字体。未安装这些字体时
保持 DejaVu Sans 和缺字警告；可在 FigureSpec 使用语义等价的英文 presentation text，
不要翻译或更改实验数据。字体/Matplotlib 版本可能影响 PDF 字节，科学数值及数据来源
不受字体选择影响。

命令示例（先用 `air question p-xxx` 核对当前问题）：

```bash
air answer p-xxx retry    # 额外一次语义调用，可能产生费用
air answer p-xxx skip     # 仅适用于语义问题；风险留给人工审批
air answer p-xxx restore  # 仅适用于文件 reconciliation；先备份再恢复
air answer p-xxx end      # 结束并保留现有产物
air resume p-xxx          # 修正来源后继续；不会绕过 evidence 校验
```
