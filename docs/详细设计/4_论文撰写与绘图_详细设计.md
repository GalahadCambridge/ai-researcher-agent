## 0. 先读这一段

**本项目的核心贡献在你这里。** 我们要回答的研究问题是：*论文里的结论有没有证据？给 Agent 加上“论断-证据检查”后，无依据的结论会不会更少？*

你的模块做四件事：

1. **画图**：用真实汇总结果生成规范的科研图；
2. **列论断**：先列出论文要说的每条结论，每条绑定到具体的汇总结果、图表或文献；
3. **写论文**：按论断清单写 LaTeX，按用户模板编译成 PDF；
4. **核验**：逐条检查数字对不对、话有没有说过头、引用是否真实存在。

贯穿全文的一个关键设计：**论文中的实验数字不由大模型手写，而是通过 LaTeX 宏从汇总结果中自动填入**。大模型决定“说哪个数”，代码决定“这个数是多少”。

第 1 周你不需要等任何人：组长会提供一个**样例项目**（含 9 个运行、汇总表和一版论文），你可以直接用它开发画图和编译。

### 3.1 图表 `artifacts/figures/<fig_id>/`

artifacts/figures/fig_c1/

```python
class FigureSpec(BaseModel):
    fig_id: str                         # "fig_c1"
    kind: Literal["bar", "line", "point", "box"]
    aggregate_id: str                   # 数据来源，如 "C1"
    x: str                              # 分组字段，如 "train_size"
    hue: str | None                     # 第二分组字段，如 "method"
    facets: list[str] = []              # 额外分组字段，最多 8 个字段、16 个分面；旧规格默认为空
    metric: str                         # "accuracy"
    error: Literal["ci95", "std", "none"]
    title: str
    xlabel: str
    ylabel: str                         # 必须含单位，如 "Accuracy (%)"
    scale: float = 1.0                  # 显示缩放，如 100 表示转为百分比
    log_x: bool = False
    caption: str                        # 必须写明 n 和误差条含义

class Figure(BaseModel):
    fig_id: str
    spec: FigureSpec
    aggregate_ref: VersionRef           # 用的是哪个版本的汇总结果
    run_ids: list[str]                  # 汇总结果的全部输入运行
    skill_ref: str                      # "scientific-plotting@0.2.0"
    script_sha256: str
    outputs: list[str]                  # pdf、png 路径
    n_per_group: dict[str, int]
    created_at: datetime
```

### 3.2 论断-证据矩阵 `paper/claims.jsonl`（每行一条论断）

```python
class ValueRef(BaseModel):              # 论断中引用的一个数字
    key: str                            # 宏键，代码生成，如 "C1.lora.500.accuracy.mean"
    aggregate_id: str
    aggregate_version: int
    group: dict                         # {"method": "lora", "train_size": 500}
    metric: str
    stat: Literal["mean", "std", "ci95_low", "ci95_high", "n", "min", "max",
                  "diff_mean", "p_value"]
    contrast: dict | None = None        # stat 为 diff_mean / p_value 时：{"a": {...}, "b": {...}}
    fmt: dict = {"scale": 100, "decimals": 1, "suffix": ""}
    rendered: str                       # 代码按 fmt 渲染出的文本，如 "84.6"

class EvidenceLink(BaseModel):
    type: Literal["aggregate", "figure", "run", "paper", "plan", "log"]
    ref: str                            # aggregate_id / fig_id / run_id / paper_id / artifact_id
    version: int | None = None
    selector: dict | None = None        # 指向汇总中的哪一行
    note: str = ""

class Comparison(BaseModel):            # 比较型论断才有
    a: dict; b: dict; metric: str
    asserted: Literal["a>b", "a<b", "a≈b"]

class Claim(BaseModel):
    claim_id: str                       # "CL3"
    section: Literal["abstract", "introduction", "related_work", "method", "setup",
                     "results", "discussion", "conclusion"]
    text: str                           # 论断原文（LaTeX，数字用 \airval{key}）
    type: Literal["numeric", "comparative", "qualitative", "citation", "method_fact"]
    statement_kind: Literal["observation", "interpretation"]
    hedge: Literal["none", "likely", "possible"]   # 解释类论断不能为 none
    importance: Literal["major", "minor"]
    hypothesis: str | None = None       # 对应 selected.md 中的 H1/H2
    values: list[ValueRef] = []
    comparison: Comparison | None = None
    evidence: list[EvidenceLink]
    location: dict | None = None        # 写作后填入：{"file": "paper/sections/results.tex", "line": 12}
```

**支持程度分级**（核验后得到，写在核验报告里，不写回 `claims.jsonl`）：

| 等级 | 含义 |
|---|---|
| `supported` | 证据存在、数值一致、措辞未超出证据范围 |
| `partially_supported` | 证据存在，但措辞偏强或条件不完全一致（如只在部分规模下成立却说“普遍”） |
| `unsupported` | 没有证据，或证据与论断无关 |
| `contradicted` | 证据与论断相反（如说 A 优于 B，数据显示 A 低于 B） |
| `unverifiable` | 证据所在文件缺失或无法读取 |

### 3.3 核验报告 `paper/review/review_v<N>.json`（同名 `.md` 给人看）

```python
class Issue(BaseModel):
    code: str                 # 见 8.1 的问题代码
    severity: Literal["blocker", "major", "minor"]
    claim_id: str | None
    location: dict            # {"file": ..., "line": ...}
    sentence: str             # 出问题的原句
    detail: str               # 如“文中 84.6，重算为 84.2”
    suggestion: str = ""

class ClaimCheck(BaseModel):
    claim_id: str
    support: Literal["supported", "partially_supported", "unsupported", "contradicted", "unverifiable"]
    issues: list[Issue]
    recomputed: dict[str, str] = {}     # 每个 ValueRef 重算后的渲染值

class CheckReport(BaseModel):
    paper_ref: VersionRef
    mode: Literal["full", "audit"]      # full：写作中核验；audit：评价时对两组论文的事后核验
    claims: list[ClaimCheck]
    unbound_issues: list[Issue]         # 不属于任何论断的问题（未绑定的数字、无效引用）
    counts: dict                        # {"blocker": 0, "major": 2, "minor": 5, "supported": 14, ...}
    compile_ok: bool
    created_at: datetime
```

## 5. 绘图 skill（`skills/scientific-plotting/`）

### 5.1 原则

- **统计图只能由真实汇总结果通过绘图脚本生成**，不能用图像生成模型（需求 6.5）；
- **大模型只决定画什么（规格），不写绘图代码**。绘图脚本是固定的、经过测试的，按 `kind` 分支。这样避免模型写错代码画出错误的图，也让每张图都可以用同一脚本重新生成。

### 5.2 默认图表规则

| 汇总结构 | 默认图 |
|---|---|
| `group_by` 含一个数值型字段（如 `train_size`）和一个类别字段（如 `method`） | 折线图：x = 数值字段，每个方法一条线，误差条 = 95% 区间 |
| 只有类别字段 | 柱状图 + 误差条 |
| 需要显示每个种子的分布 | 点图（每个点是一个运行）叠加均值 |

### 5.3 脚本接口

```bash
python skills/scientific-plotting/scripts/plot.py --spec spec.json --data data.csv --out artifacts/figures/fig_c1/
```

- `data.csv` 由 `figures.py` 从汇总结果导出：每行一组，列 = 分组字段 + `mean, std, ci95_low, ci95_high, n` + 各个原始值；
- 统一样式（`templates/air.mplstyle`）：字体大小、色盲友好配色、无多余边框；
- 同时输出 PDF（论文用）和 PNG（GUI 预览用）；
- 输出后复制 PDF 到 `paper/figures/<fig_id>.pdf`。

### 5.4 验证规则（`validators.py`）

| 规则 | 不通过 |
|---|---|
| `xlabel`、`ylabel` 非空，`ylabel` 含单位或明确无量纲 | 拒绝 |
| 每组 n ≥ 2 时必须有误差条 | 拒绝 |
| `caption` 中写明 n 和误差条含义（如 “error bars: 95% CI over 3 seeds”） | 拒绝 |
| `data.csv` 中每个值都能在汇总结果中找到 | 拒绝 |
| 汇总结果的 `eval_condition` 为 `explore` 时，标题或图注必须注明“探索性” | 拒绝 |

每张图用 `ctx.archive.put()` 登记，`parents` = 所用汇总结果的版本——这就是证据链中“图表 → 汇总”的一环。

## 6. 论断-证据矩阵（`claims.py`，仅开启证据检查时）

### 6.1 生成步骤

1. 大模型（strong）读取证据包，输出 `claims` 列表：每条写清楚 `section`、`type`、`statement_kind`、`hypothesis`、要引用哪些数字（用 `aggregate_id + group + metric + stat` 描述）、证据链接、比较方向；
2. **代码逐条解析数字**：用 `services.runs.resolve_value()` 取值，按 `fmt` 渲染为 `rendered`，生成 `key`。解析失败（组不存在、统计量不存在）的论断退回给模型修改一次，仍失败就删除并记录；
3. 代码检查比较方向：`asserted="a>b"` 但 `diff_mean ≤ 0` 的论断，直接退回给模型（这是最常见的“结论与数据相反”）；
4. 保存 `paper/claims.jsonl`，`parents` = 证据包引用的全部汇总结果和图表版本。

### 6.2 论断清单的规则（写在 `latex-writing` skill 的说明里）

- 每个假设至少对应一条 `results` 中的观察型论断；
- `results` 章节**只放观察**（`statement_kind="observation"`）：只陈述“看到了什么”；
- `discussion` 放解释（`interpretation`），必须带 `hedge`（likely/possible），并尽量写出其他可能的解释；
- 方法不如基线、结果不显著的情况同样要写成论断，不能省略（需求 6.6：负面结果也是有效发现）；
- 来自文献的论断（`type="citation"`）必须链接 `paper_id`。

### 6.3 数字宏 `paper/air_values.tex`

代码根据 `claims.jsonl` 生成：

```latex
% 由 airesearcher 自动生成，请勿手工修改
\makeatletter
\newcommand{\airval}[1]{\@ifundefined{airval@#1}{\textbf{??#1??}}{\@nameuse{airval@#1}}}
\makeatother
\expandafter\def\csname airval@C1.lora.500.accuracy.mean\endcsname{84.6}
\expandafter\def\csname airval@C1.full_ft.500.accuracy.mean\endcsname{84.2}
```

正文中写 `LoRA reaches \airval{C1.lora.500.accuracy.mean}\% accuracy`。好处：

- 数字永远与汇总结果一致；
- 汇总结果更新（例如补跑了种子）后，只需重新生成 `air_values.tex` 并编译，数字自动更新（FR-42）；
- 未定义的键会在 PDF 中显示为醒目的 `??key??`，不会悄悄出错。

### 6.4 论断标记

正文中每条论断用宏包裹，方便核验定位和 GUI 跳转：

```latex
\claim{CL3}{LoRA reaches \airval{C1.lora.500.accuracy.mean}\% accuracy with 500 training examples,
compared with \airval{C1.full_ft.500.accuracy.mean}\% for full fine-tuning.}
```

`\claim{id}{text}` 在正式 PDF 中只输出 `text`；在“审阅版”PDF（`paper.review_build: true`，第 3 周视时间）中，在句末加一个上标链接 `[CL3]`，指向 GUI 中该论断的证据页。

## 7. LaTeX 写作 skill（`skills/latex-writing/`）

### 7.1 章节结构（FR-40）

默认章节：摘要、引言、相关工作、方法、实验设置、结果、讨论（含局限性）、结论，外加**生成式 AI 使用声明**（需求 7.3：披露 Agent 的使用范围、人工审核范围和已知限制，由代码根据审批记录生成，不由模型编写）。用户模板有自己的章节要求时服从模板。

### 7.2 分章节写作

每章一次模型调用，输入：

| 章节 | 主要输入 |
|---|---|
| 摘要、结论 | 本章相关论断（开启时）或证据包摘要（关闭时） |
| 引言、相关工作 | `selected.md`、文献综述、差异表、可引用论文表（`citation_key → 标题、年份、是否仅摘要`） |
| 方法、实验设置 | `selected.md`、实验计划、任务配置、环境摘要 |
| 结果 | 结果章节的论断 + 图表清单（开启时）；汇总表 + 图表清单（关闭时） |
| 讨论 | 解释型论断 + 已批准的重要过程日志 |

写作规则（写在 skill 的 `SKILL.md` 中）：

- 只能用 `\cite{key}` 引用“可引用论文表”中的键；
- 开启时，结果中的每个数字都必须用 `\airval{}`，每条论断用 `\claim{}{}` 包裹，**不允许出现清单之外的结果论断**；
- 图用 `\includegraphics{figures/<fig_id>.pdf}`，图注使用 `FigureSpec.caption`；
- 仅基于摘要的论文，只能引用其主要结论，不能描述实验细节。

输出写到 `paper/sections/<section>.tex`。

### 7.3 模板导入与检查（FR-47）

**用哪个模板：** 由 `project.yaml` 的 `template` 决定（主干详细设计 3.10）：

- `null` → 默认模板 `skills/latex-writing/templates/default/`（普通 `article`，随 skill 版本管理）；
- `{id: tpl-01, version: 2}` → 用户上传的模板。上传由主干完成：解压到 `templates/<tpl_id>/v<N>/original/`、登记版本，并更新 `project.yaml`——**原始模板永远不修改**。用户在写作阶段中途上传新模板，下一次 `step` 会发现模板版本变化，从 `template` 步骤重新开始。
  **主干已实现（v0.6）：** `POST /templates`、`air template upload`（安全检查见主干详细设计附录 B 第 9.2 行）；同一版本目录下还有 `upload.json`（原文件名、sha256、上传时间）。你的 `check.json` 写在 `templates/<tpl_id>/v<N>/check.json`，`GET /templates` 和 `air template list` 会原样显示。

**检查（`template.py`，结果写 `templates/<tpl_id>/v<N>/check.json`，与 `original/` 并列，不改原始文件）：**

    entry_candidates: list[str]       # 含 \documentclass 的顶层 .tex 文件
    entry: str | None                 # 选定的入口

## 8. claim-review（`skills/claim-review/`、`services/evidence.py`、`stages/writing/review.py`）

### 8.1 检查项与问题代码

前六项是**确定性检查**（`services/evidence.py`，不调用模型，可重复运行），后三项需要模型判断（`review.py`）。

| # | 检查 | 问题代码 | 严重度 |
|---|---|---|---|
| 1 | 每个 `ValueRef` 用 `recompute_aggregate()` 从原始指标重新计算，按 `fmt` 渲染后与 `rendered` 比较 | `NUM_MISMATCH` | blocker |
| 2 | 正文中不在 `\airval{}` 里的数字（排除年份、章节号、引用编号、图表编号），尝试与证据包中的任何汇总值匹配（容差 = 显示精度最后一位的一半） | `NUM_UNBOUND`（结果、摘要中为 major，其他为 minor） | major / minor |
| 3 | 论断引用的汇总结果包含失败、试运行或被标为 invalid 的运行；或汇总版本不是最新 | `INVALID_RUN` / `STALE_EVIDENCE` | blocker / major |
| 4 | 主要论断引用了 `eval_condition=explore` 的结果却未标注“探索性”；文中声称的种子数/样本数与 `n` 不符 | `CONDITION_MISMATCH` / `N_MISMATCH` | major |
| 5 | 比较型论断：`a>b` 但 `diff_mean ≤ 0` → 相反；`diff_mean > 0` 但 95% 区间重叠且 `hedge="none"`、措辞为“优于/显著” | `CONTRADICTED` / `OVERCLAIM_SIGNIFICANCE` | blocker / major |
| 6 | 每个 `\cite` 调用 `verify_citation()`：`not_in_archive` | `CITATION_NOT_IN_ARCHIVE` | blocker |
| 6' | 引用了仅基于摘要的论文来支持实验细节 | `CITATION_ABSTRACT_ONLY` | minor |
| 7 | **范围检查（模型）**：把相关写成因果；推广到未测试的数据集/模型/规模；没有提及已知局限 | `OVERCLAIM_CAUSAL` / `OVERCLAIM_SCOPE` / `MISSING_LIMITATION` | major |
| 8 | **未绑定的论断（模型）**：结果、摘要、结论中未被 `\claim{}` 包裹、但确实在陈述实验结果的句子 | `NO_EVIDENCE` | major |
| 9 | **观察与解释混写（模型）**：结果章节中出现解释性语句 | `MIXED_INTERPRETATION` | minor |

每个论断的支持程度由其问题决定：有 `CONTRADICTED` → contradicted；有 blocker 或 `NO_EVIDENCE` → unsupported；有 major → partially_supported；证据文件缺失 → unverifiable；否则 supported。

### 8.2 模型判断部分的要求

- 每次只给模型一小段（一条论断 + 它的证据数值 + 上下文两句），而不是整篇论文，减少遗漏；
- 输出必须引用原句（`sentence`），代码检查原句确实存在于正文中，不存在的问题被丢弃；
- 提示中给出判断标准和正反例（写在 `skills/claim-review/SKILL.md`），例如：“在 3 个种子、单一数据集上观察到的差异，不能写成 ‘LoRA is better for low-resource classification’，应写成 ‘on SST-2 with 500 examples, LoRA achieved higher mean accuracy (3 seeds)’。”

### 8.3 修改循环

- 存在 blocker 或 major → `revise`：把问题列表交给模型，只重写涉及的论断和句子（必要时修改 `claims.jsonl` 中的论断，数字仍由代码解析）→ 重新编译 → 重新核验；
- 最多 `paper.max_review_rounds`（默认 2）轮；
- 仍有问题也提交审批，但在审批摘要和核验报告中**醒目列出剩余的 blocker**。GUI 在有 blocker 时要求用户填写意见才能批准（见详细设计 5）。

## 13. 评价：主对照实验协议（你牵头）

**这一节是最终报告“严格实验比较”部分的核心，第 2 周末前要定稿，第 3 周中冻结配置后不再修改。**

### 13.1 设置

| 项 | 内容 |
|---|---|
| 比较 | 完整系统（`evidence_check: true`）vs 消融系统（`false`），其余全部相同（主干批量工具保证） |
| 问题实例 | 同一任务族的 3 个实例（与实验同学商定，例如：不同训练规模区间、不同数据集、不同方法对） |
| 轨迹数 | 每实例每组重复 k 次，k 由成本试点决定（建议 3，最少 2）；样本有限要在报告中说明 |
| 固定条件 | 模型与提示版本、检索快照、初始实验模板、预算、审批策略（auto-approve，两组一致） |
| 区分两种重复 | 一条“轨迹”内部的种子重复 ≠ 不同轨迹之间的重复；统计时以轨迹为单位 |

### 13.2 事先定义的指标

| 指标 | 定义 |
|---|---|
| **无证据主要论断率**（主要指标） | 被判为 unsupported 或 contradicted 的主要论断数 / 主要论断总数 |
| **数值一致率** | 与实验记录一致的受检数字数 / 受检数字总数 |
| 任务完成率 | 到达 ManuscriptPending 的轨迹数 / 启动的全部轨迹数 |
| **防止“少写就少错”** | ① 预设研究问题覆盖率：论文中有结论的假设数 / 假设总数；② 论文完整度：必需章节、图表是否齐全（检查表）；③ 有效结论数：supported 的主要论断数 |
| 成本 | 每条轨迹的 LLM 费用、token、时长（来自主干 `summary.csv`） |

**主要论断的定义：** 摘要、结果、讨论、结论中，陈述实验结果或对其解释的句子级论断，包括数字、比较、因果或归因、泛化陈述。背景介绍、方法描述、文献综述不计入。

### 13.3 论断抽取与评判流程

1. **抽取（两组同法）：** 对每篇最终论文，用 `services.evidence.audit()` 让模型从正文中抽取候选主要论断（不使用 `claims.jsonl`，因为消融组没有它）；
2. **匿名化：** 重新编译两组论文为“干净版”（去掉 `\claim` 标记，宏已展开为数字），随机编号为 `paper-01 … paper-NN`，打乱顺序；编号与组别的对应表由组长保管；
3. **证据包：** 为每篇论文从研究档案生成统一格式的证据包（汇总表、运行列表、计划、文献清单），格式与组别无关；
4. **人工评判：** 两名盲评员（GUI 同学、文献同学）各自独立：先确认/增删候选论断清单，再按 3.2 的五个等级判定每条论断；同时为论文整体打分（13.4）；
5. **分歧处理：** 计算两人在支持等级上的一致性（Cohen's κ）；分歧条目两人讨论后达成一致，仍无法一致的标“有争议”，在报告中单独列出，不由第三人裁定；
6. **辅助：** 自动核验（`check()` 的确定性部分 + 模型判断）作为参考，与人工结果对比报告其一致率，**不作为唯一裁判**（需求 8.3）。

### 13.4 论文整体评分标准（每项 1~5 分）

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 结论与证据一致 | 多处结论无依据或与数据相反 | 个别结论偏强 | 结论均有依据，措辞与证据强度匹配 |
| 完整性 | 缺主要章节或主要结果 | 结构完整但部分结果未讨论 | 所有预设问题都有结论 |
| 负面结果与局限 | 隐瞒或淡化负面结果 | 提到但不充分 | 如实报告并分析局限 |
| 清晰度 | 难以理解 | 基本清楚 | 清楚易读 |

评分表模板放在 `eval/rubric/`；评分结果录入 `eval/results/blind_review.csv`。

### 13.5 统计与报告

- 以轨迹为单位，报告每组的均值和 bootstrap 95% 区间；按实例配对比较；
- 样本量小，不做强显著性结论，如实写“观察到的差异”与区间；
- 无论结果是改进、无差别还是变差，都如实报告（需求 2.3）；
- 附代表性的成功与失败案例各 1~2 个（截取论断、证据和判定）。

### 13.6 复现核心实验（你负责执行）

- **你没有写实验流程**，所以由你来做（需求 8.3）：在另一台电脑或全新的 Python 虚拟环境中，只按 `environments/<env_hash>/REPRODUCE.md` 操作，重跑主要比较涉及的运行；
